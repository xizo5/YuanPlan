## 第一轮主体功能

1. **T16–T17 任务与子任务**：状态、执行人（含未分配）、优先级、标签、截止日期范围筛选；补开始日期输入；列表展开子任务，详情进入子任务及返回父任务；子任务、我的任务分页。筛选后的列表包含匹配的子任务，看板仍以父任务为卡片。
2. **T18 看板**：四列独立加载和分页；卡片拖到目标卡片前，拖到列区域则追加至该列末尾；提供上移按钮和详情状态选择作为非拖拽入口。排序事务锁定项目，检查被移动任务及目标卡片版本，保留幂等结果，只为实际移动任务增加版本。排序间距耗尽时内部重排不产生其他任务的虚假内容版本。
3. **T19 活动与评论**：统一任务、评论、关联文档事件时间线；分页；管理员软删除评论。普通成员的活动接口及评论接口均不返回已删除评论原文，管理员仍可追溯。
4. **T21–T22 Wiki**：目录加载更多、标题及正文搜索、修改上级文档；共享编辑器添加表格、行列操作及 Wiki 图片上传，图片沿用受控文件接口。
5. **T23 保存与恢复**：按账号/项目/文档隔离本地草稿，重载后明确选择恢复或丢弃；保存请求保留幂等键，成功后清除草稿；中文组合输入期间暂停保存；冲突时并排展示本地及服务器正文，用户确认后基于新版本继续编辑，并需手动保存；退出登录清除该账号草稿。
6. **T24 历史**：按来源、操作人名称、UTC 日期过滤；展示保存前后字段及富文本正文；恢复仍生成新版本。显式无变化保存也会提交一个版本，自动保存无变化则跳过。
7. **T25 关联**：任务中检索并选择文档，文档显示反向关联任务；双方链接可打开对应详情，沿用项目权限。
8. **T29 生命周期**：管理员项目管理页、任务/文档回收站、任务归档列表、归档/取消归档/软删除/恢复确认界面；项目列表提供项目回收站。项目归档后必须先取消归档才能恢复其中内容。

## 第二轮：标签、团队与 Wiki 排序（2026-09-18 验证完成）

- **统一项目标签**：增加项目标签注册表，迁移时从既有任务回填。项目管理员和成员可创建、改名，管理员可删除；改名与删除在同一事务内同步全部相关任务（包括归档、软删除任务），每个受影响任务追加版本与审计。历史快照不修改。被删除的名称保留为停用记录，避免旧客户端静默重新创建；目前重新使用该名称会返回明确错误。
- **兼容现有调用**：任务及 MCP 的 `labels` 字符串数组契约保留，由服务在任务事务中注册/校验本项目标签；本轮没有改成标签 ID 数组或新增 `task_labels` 关联表。这是相对逻辑实体设计的实现调整，标签管理及批量同步集中在 `modules/labels.ts`。
- **团队与项目成员管理**：团队改名、管理员/成员角色调整、成员移除、团队删除；邀请记录与撤销；项目内从可见团队多选人员入项目、移除项目成员。团队邀请不再展示只读角色。最后管理员保护在服务端事务中执行，并验证并发降级只能成功一次。
- **项目基本信息**：管理员可修改项目名称、简介与关联团队。没有团队权限的项目管理员可保留已有团队关联，但不能改为无权访问的新团队。团队成员身份不自动授予项目权限；移出/删除团队不移除既有项目成员。
- **Wiki 同级排序**：目录增加上移/下移按钮，服务端校验当前版本和实际相邻页面的 ID/版本，只允许同级移动；移动产生正文完整快照，其他页面不生成虚假内容版本。搜索模式不显示排序按钮。
- **数据库迁移**：`0003_project_labels_team_versions.sql` 增加标签注册表和团队版本，已应用于本地开发库及集成测试库。
- **实现文件**：`apps/server/src/modules/labels.ts`、`projects.ts`、`resources.ts`、`app.ts`；`apps/web/src/Labels.tsx`、`Settings.tsx`、`Lifecycle.tsx`、`ProjectPage.tsx`、`Wiki.tsx`。

## 第三轮：账号恢复与文件维护（2026-09-18）

- 增加登录页找回入口、邮件恢复 API 和主机恢复 CLI。邮件使用通用响应及账号冷却时间；主机 CLI 仅签发已有有效实例管理员的一次性链接，记录系统来源、操作系统用户、主机和原因。
- 恢复消费与签发按目标账号加锁，防止并发重放。重置后撤销会话及 MCP 凭据；停用账号同时作废恢复链接。系统审计身份不可登录、不可启用，并从首次安装判断中排除。
- 新增默认预览的 `files-clean` 命令。只考虑超过至少 24 小时、数据库未登记的直属普通 UUID 文件，跳过符号链接、子目录和其他文件。所有已登记附件（包括历史引用）保留。
- 上传与清理使用共享/独占数据库维护锁，防止扫描误删正在提交的上传；删除前再次核对文件属性。上传失败不立即删除落盘文件，避免提交回执丢失时破坏实际已提交的附件。
- 交付 `apps/server/src/cli.ts`，构建生成 `dist/cli.js`，提供开发/生产两套 npm 运维入口；已应用迁移 `0004_recovery_system_actor.sql`。
- 开发库只执行清理预览：6 个附件均有数据库登记，实际删除数为 0。删除行为仅在独立测试目录验证；没有签发或消费真实本地管理员的恢复链接。
- 使用方式与边界见 [恢复和文件维护指南](../deployment/recovery-and-files.md)。
