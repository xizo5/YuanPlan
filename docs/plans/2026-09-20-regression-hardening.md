# V1 权限与故障回归补齐

日期：2026-09-20。执行依据：已确认的 V1 计划与“恢复测试环境 → T30/T31 → MCP/SMTP → 部署恢复 → 性能 → 发行”顺序。

## 设计与范围

本轮沿用既有角色、审计和保存语义，使用真实 PostgreSQL 锁等待观测、实际 HTTP 连接和独立 API 子进程验证边界。与只模拟异常或直接进行生产故障演练相比，这种方式可重复定位事务问题，且不需要中断开发实例。

账号停用与业务写入必须遵循同一锁顺序：先锁用户，再锁项目。停用先取得目标用户锁时，后续写入等待后被拒绝；已取得用户共享锁的写入可先完成，停用随后生效。停用后的新请求和幂等回执重试均被拒绝。

故障验证仅使用 `_test` 数据库和测试新建资源。响应丢失测试由本地代理读完上游响应后断开客户端连接；进程中断测试在审计插入被数据库锁阻塞时终止测试 API 子进程，随后验证回滚及重启重试。

## 本轮实现

- 修复 `setUserDisabled` 的项目锁 → 用户锁顺序与业务写入相反造成的死锁。新增用户行锁并提前校验目标存在性，不改变最后管理员保护。
- 新增停用先行、写入先行两个确定性并发用例，验证任务内容、版本、历史及停用后重试。
- 新增团队邀请人降级、移除及团队删除后，排队接受请求被拒绝的用例；同时验证没有新增成员、没有消费邀请、没有接受审计。
- 新增真实 HTTP MCP 写入响应丢失后的同操作编号重试：只产生一个写入版本及一条对应审计。
- 新增 API 子进程终止测试：任务更新后、审计插入前终止进程，验证业务、版本与回执均未提交；重启后相同操作可以成功。
- 修复维护测试在数据库初始化失败时的清理逻辑，避免不存在的临时目录产生第二个错误，并确保连接池关闭。

复现新增服务回归：

```bash
npm test -- tests/authorization-races.test.ts tests/transport-failures.test.ts
```

测试需要有效 `.env`、运行中的 PostgreSQL，以及名称以 `_test` 结尾的 `TEST_DATABASE_URL`。故障测试启动临时 Node 子进程及回环 HTTP 端口，只终止自己创建的子进程；会短暂独占测试库审计表，不能与其他测试库使用者并行运行。
