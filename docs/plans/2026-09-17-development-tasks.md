# YuanPlan V1 开发任务与验收计划

日期：2026-09-17\
状态：MVP 已实现，主体功能持续补齐；部分实现已通过集成与浏览器回归，尚未完成 V1 全量验收。实际变更、验证及剩余项见[主体功能开发进度](./2026-09-17-core-development-progress.md)。\
依据：[产品与技术设计](./2026-09-17-project-management-design.md)、[UI 方案](./2026-09-17-ui-direction.md)、[讨论记录](./2026-09-17-product-discovery.md)。

## 1. 执行规则

- 先完成 T01 对建议默认值和范围的集中审阅，再开展依赖这些决策的应用代码实现。正式许可证是公开发布前的必要决定，不要求为私有开发提前猜定。
- 开发按依赖推进，权限、审计、并发和数据模型先于业务页面，MCP 共用业务服务。
- 一个任务完成须交付实现、必要测试、文档及验收证据；“页面看起来可用”不是完成条件。
- 不复刻 Kaneo/Plane 源码；基础组件优先复用 Mantine 和合适的成熟库。
- 每个任务至少记录：状态、实际变更文件、测试命令及结果、已知限制、关联设计条目。发现范围变化先更新设计与任务，不能悄悄扩大首版。
- 下列文件位置是规划目标路径；实际实现已位于 apps、packages、tests，部分模块合并于服务文件，映射见进度记录。

## 2. 阶段、顺序与投入区间

估算假设：一名熟练全栈开发者全职投入，使用 AI 辅助，需求基本稳定，组件可直接使用。人日包含实现、联调与验证，不是保证工期，不包含需求反复、审批等待或开发者学习时间。

| 阶段 | 任务 | 阶段验收结果 | 估算人日 |
|---|---|---|---:|
| M0 设计与技术验证 | T01–T03 | 关键默认值、组件与 MCP 接入路线可执行 | 4–6 |
| M1 工程与基础能力 | T04–T11 | 统一 UI、登录邀请、权限、审计与事务底座 | 12–18 |
| M2 项目与团队 | T12–T14 | 可以独立建项目、邀请人员、选择团队成员 | 6–9 |
| M3 任务闭环 | T15–T20 | 列表、看板、子任务、评论、附件实际可用 | 12–18 |
| M4 Wiki 与追溯 | T21–T25 | 编辑、冲突、历史、恢复、链接和搜索闭环 | 12–18 |
| M5 AI 接入 | T26–T28 | 实际 MCP 客户端可授权地读取与修改 | 6–9 |
| M6 生命周期与体验 | T29–T30 | 归档、回收站、角色边界、统一界面完成 | 4–6 |
| M7 交付验证 | T31–T36 | 回归、性能、部署、恢复及发行资料完成 | 12–18 |
| 合计 | 36 项 | 可供首批小团队使用和交付的 V1 | 68–102 |

按每周 5 个有效工作日约 14–21 周。比早期“核心流程原型”估算更完整，已包含每次保存留痕、历史恢复、MCP、备份恢复和发行验证。可以在 M3 后内部试用任务管理，但不能把此时的版本当作完整需求交付。

## 3. 详细开发任务

### T01 — 设计基线与首版范围确认

- 依赖：无。
- 工作：集中审阅设计 D01–D14；确认语言/主题、团队关联数量、邀请默认值、子任务展示、删除恢复、文档目录、附件限制及性能数据集；确定首发 MCP 客户端。记录未决定项的阻塞范围。
- 交付：更新设计、决策表、首版功能清单及范围外清单；正式品牌和许可证可列为发行阻塞项。
- 验收：所有会改变数据模型或用户行为的默认值有明确结论；不会把提案标成用户已确认；后续任务引用同一基线。

### T02 — 依赖兼容与 UI/编辑器/认证验证

- 依赖：T01。
- 工作：选择仍受支持的 Node.js LTS 与稳定依赖版本；验证 React/Vite/Mantine、Mantine Tiptap 集成、Drizzle/PostgreSQL 和 Better Auth 的安装、构建、基本交互与迁移；验证开源扩展覆盖所需编辑格式。选择一套图标、成熟拖拽库及测试工具。
- 交付：`docs/architecture/dependencies.md`，版本与许可证清单、兼容验证结果、需替换的依赖说明。
- 验收：构建可复现；所需组件不是付费扩展才能使用；没有混装不兼容编辑器主版本；不依赖未核实的“最新版本”或未经验证的内存宣传。

### T03 — MCP 接入兼容验证

- 依赖：T01。
- 工作：用官方 SDK 验证 Streamable HTTP、握手、工具调用、身份传递、Origin 检查和结构化错误；验证两种选定客户端是否支持预配置认证头。必要时验证 stdio 桥接或确定 OAuth 工作量。
- 交付：`docs/architecture/mcp-compatibility.md`，锁定协议/SDK/客户端版本及接入路径。
- 验收：两种客户端都能调用受认证的样例工具并收到正确错误；不能以匿名成功调用代替认证验证；PAT 不能标成完整 OAuth 实现。若需 OAuth 超出估算，先修订任务。

### T04 — 仓库、构建与开发环境

- 依赖：T02、T03。
- 目标位置：`apps/web`、`apps/server`、`packages/contracts`、`packages/editor-schema`、`deploy`、`tests`。
- 工作：建立简单 workspace、类型检查、代码检查、环境变量验证、锁文件、测试框架及开发数据库；区分开发、测试、生产配置。定义共享错误和分页结构。
- 验收：全新环境按文档可以安装、启动、测试和构建；样例配置不含秘密；缺配置时明确报错；生产构建不使用开发服务器。

### T05 — 数据模型、约束和迁移

- 依赖：T04。
- 目标位置：`apps/server/src/db`、`apps/server/migrations`、`docs/architecture/data-model.md`。
- 工作：按设计实体输出 ER 图与 Drizzle schema；建立项目归属、成员唯一、任务编号、资源版本唯一及外键约束；设计软删除和不可变文件引用；定义运行账号和迁移账号权限。
- 验收：空库迁移成功；重复部署不会重复迁移；跨项目父任务/文档/标签关联不可写入；软删除不级联清空历史；迁移及应用数据均可通过测试数据库检验。

### T06 — Mantine 主题、应用布局和样板页

- 依赖：T04。
- 目标位置：`apps/web/src/theme`、`apps/web/src/components`、`apps/web/src/layouts`。
- 工作：统一主题变量、图标、导航、页面标题、筛选栏、任务卡片、状态与优先级；样板展示表单、弹窗、抽屉、通知及各类反馈。落实选定主题与窄屏布局。
- 验收：基础组件来自 Mantine；无第二套通用 UI；键盘可用、焦点可见、图标按钮具名；长标题、错误、空白、只读和保存状态一致；用户可审阅样板。

### T07 — 初始化、登录与注册

- 依赖：T05。
- 目标位置：`apps/server/src/modules/auth`、`apps/server/src/modules/instance`、`apps/web/src/features/auth`。
- 工作：集成成熟认证库；实现有一次性设置凭据的初始化、登录、退出、注册模式和账号停用检查；会话、Cookie、CSRF/Origin、限流及错误提示按部署方式配置。
- 验收：仅邀请模式不能绕过邀请注册；公开注册的邮箱验证满足 T01 决策；初始化并发只成功一次；停用账号新请求被拒绝；错误与日志不泄露密码或账号敏感信息。

### T08 — 邀请与邮件发送

- 依赖：T07、T09。
- 目标位置：`apps/server/src/modules/invitations`、`apps/server/src/modules/mail`、`apps/web/src/features/invitations`。
- 工作：邀请令牌摘要、邮箱/目标/角色绑定、期限、撤销与单次消费；邮件可选，支持手动复制链接。需要可靠邮件重试时使用数据库持久任务，不依赖内存队列。
- 验收：错邮箱、过期、撤销、重复消费、篡改角色、邀请人失去管理权均有测试；无邮件不会虚假标记邮箱已验证；开放注册不授予既有项目权限；手动交付链路可用。

### T09 — 统一权限服务

- 依赖：T05、T07。
- 目标位置：`apps/server/src/modules/authorization`、`packages/contracts`。
- 工作：实现管理员/成员/只读矩阵、项目和团队独立授权、最后管理员保护及账号状态检查；后续网页 API 与 MCP 必须共用；定义不可访问资源的统一响应策略。
- 验收：表驱动用例覆盖所有角色、非成员、跨项目、停用账号、归档资源；系统管理员不直接绕过项目权限；成员编辑不限本人任务；并发降级无法留下零管理员。

### T10 — 账号恢复与系统管理

- 依赖：T07、T09、T11。
- 目标位置：`apps/server/src/modules/instance`、`apps/web/src/features/settings`、`apps/server/src/cli`。
- 工作：邮件找回、无邮件的管理员签发恢复链接、主机端紧急恢复、注册设置和邮件配置；恢复与账号启停记录实例管理事件，撤销旧会话和相关凭据。
- 验收：一次性恢复链接不可重放；管理员不读取用户密码；秘密不通过普通设置接口返回；最后项目管理员账号停用要求先交接；恢复操作有责任主体且清楚标注高信任运维边界。

### T11 — 保存事务、版本、审计与幂等底座

- 依赖：T05、T09。
- 目标位置：`apps/server/src/modules/audit`、`apps/server/src/modules/versions`、`apps/server/src/lib/transactions`。
- 工作：实现统一 ActorContext、expected_version、操作 ID、幂等键、事务保存、快照及审计追加；运行数据库账号禁止修改/删除历史。审计身份只来自服务端认证上下文。
- 验收：审计写入失败则业务回滚；同版本并发保存只有一个成功；同键同内容重试返回原结果、同键不同内容拒绝；提交后丢响应仍可重试查回；无变化显式保存有记录；伪造 actor 无效；权限/冲突失败不伪装成成功保存。

### T12 — 项目生命周期基础

- 依赖：T09、T11。
- 目标位置：`apps/server/src/modules/projects`、`apps/web/src/features/projects`。
- 工作：项目创建、详情、可访问列表、编辑、成员关系及创建者成为管理员；保留归档/软删除字段，实际交互在 T29 完成。
- 验收：个人不用创建团队就能创建项目；他人项目不可枚举或直接读取；创建项目与初始管理员在同一事务完成；失败不会留下无管理员项目。

### T13 — 可选团队与人员选择

- 依赖：T12。
- 目标位置：`apps/server/src/modules/teams`、`apps/web/src/features/teams`。
- 工作：团队创建、名单、管理角色、关联项目、从可见团队选择人员；区分项目管理权与团队访问权。
- 验收：团队关联不授权；团队新增成员不自动进入项目；团队管理员看不到自己无项目权限的任务或文档；删除团队保留项目；团队人员选择不暴露其他团队名单。

### T14 — 项目成员及协作界面

- 依赖：T06、T08、T12、T13。
- 目标位置：`apps/web/src/features/members`、项目/团队服务。
- 工作：直接邀请、团队选人、角色修改、成员移除及权限提示；当前名单与历史身份区分显示。成员移除的任务处理在 T29 联调。
- 验收：所有邀请方式得到相同权限结果；只读不能进入写操作；角色变化在新请求生效；最后管理员保护前后端一致；菜单和实际 API 权限一致。

### T15 — 任务领域与 API

- 依赖：T12、T11。
- 目标位置：`apps/server/src/modules/tasks`、`packages/contracts`。
- 工作：创建、读取、更新、编号、四态、优先级、日期、执行人、标签和版本化保存；按项目成员校验执行人，支持未分配。
- 验收：只需标题即可创建；创建者与执行人独立；四态自由流转；完成时间及重新打开正确；不存在跨项目标签/执行人；日期不合法拒绝；每次保存均有操作者、快照与差异。

### T16 — 任务列表、详情与我的任务

- 依赖：T06、T15。
- 目标位置：`apps/web/src/features/tasks`。
- 工作：列表分页、状态/执行人/优先级/标签/日期筛选、快速创建、详情抽屉和独立链接、富文本描述基础编辑；我的任务限定本人且仅包含可访问项目。
- 验收：标题创建顺畅；编辑失败保留输入；角色正确限制操作；筛选与刷新结果一致；不会一次加载全部任务；任务详情可直接打开并正确验证权限。

### T17 — 一层子任务

- 依赖：T15、T16。
- 目标位置：任务服务、任务详情和列表组件。
- 工作：同项目父子关系、子任务创建和编辑、父任务进度、列表展开及详情入口；实现深度和循环约束。
- 验收：不能创建孙任务、循环或跨项目父子关系；父任务状态不自动变化；归档/删除对子任务进度影响符合设计；我的任务和搜索能找到本人子任务。

### T18 — 固定四列看板与并发排序

- 依赖：T16、T17。
- 目标位置：`apps/web/src/features/board`、任务排序服务。
- 工作：四列固定展示、成熟拖拽库集成、列内顺序、按列分页及非拖拽操作；版本校验失败回退临时 UI 状态，保留用户提示。
- 验收：不能增删改名排序列；跨列移动更新真实任务状态并留记录；两个客户端并发移动不静默覆盖；仅移动当前任务时不伪造其他任务编辑；只读不能操作；触屏和键盘有替代入口。

### T19 — 评论及任务活动时间线

- 依赖：T15、T11、T06。
- 目标位置：`apps/server/src/modules/comments`、任务活动组件。
- 工作：评论新增/分页读取/管理员软删除；将评论、字段修改、状态和执行人变更展示为统一时间线，显示操作人和来源。
- 验收：重复请求不重复发表评论；只读不能评论；删除后管理员可追溯原记录；跨项目读评论失败；显示名变更不改变历史责任主体；失败保存不显示为成功活动。

### T20 — 附件与受控文件存储

- 依赖：T12、T11、T06。
- 目标位置：`apps/server/src/modules/files`、`apps/web/src/components/attachments`。
- 工作：限额上传、临时文件、安全命名、不可变存储键、元数据、业务绑定和受控下载；文件与历史引用关联；设计孤立临时文件清理。
- 验收：无权限不能靠文件 URL 下载；超限、路径穿越与危险预览被处理；上传中断不会生成成功引用；文件落盘失败不提交资源版本；历史引用文件不会被孤立清理移除；容器重建附件仍在。

### T21 — Wiki 数据模型、目录与 API

- 依赖：T12、T11。
- 目标位置：`apps/server/src/modules/documents`、`packages/editor-schema`。
- 工作：文档标题、目录、排序、Tiptap JSON schema、正文纯文本提取、版本字段及同项目链接基础；按确认层级约束目录。
- 验收：目录不会循环或跨项目；标题/正文/目录变化都留痕；非法富文本节点拒绝；只读可读不能写；删除非空目录规则明确；当前正文和版本快照一致。

### T22 — Wiki 编辑器与文档页面

- 依赖：T06、T20、T21。
- 目标位置：`apps/web/src/features/documents`、共享编辑器组件。
- 工作：Mantine Tiptap 工具栏、页面树、标题/列表/代码块/图片/表格/链接、Markdown 输入快捷方式及只读展示；与任务描述共享编辑器 schema 和样式。
- 验收：粘贴、中文输入法、长文、代码和表格可用；图片使用受控附件；无脚本注入；工具栏风格一致；只读页面不显示可编辑假象；首屏不加载所有文档正文。

### T23 — 自动保存、本地草稿与冲突处理

- 依赖：T22、T11。
- 目标位置：文档保存状态机和 API 更新服务。
- 工作：延迟自动保存、输入法组合输入保护、单文档写入排队、幂等重试、明确保存状态、本地草稿恢复与版本冲突界面；离开页面时处理未保存内容。
- 验收：无变化不自动提交；每个成功提交都有独立版本；网络失败不显示已保存；提交成功但丢响应不重复版本；两个浏览器编辑不覆盖；账号退出/切换后本地草稿不泄露给另一账号；项目归档或权限撤销时停止写入并提示。

### T24 — 历史、差异与 Wiki 版本恢复

- 依赖：T23、T16、T19。
- 目标位置：`apps/web/src/features/history`、版本查询与恢复服务。
- 工作：任务字段差异、文档版本列表及内容差异、来源/账号/时间筛选、内容恢复；历史分页和只读访问。
- 验收：任意版本能还原；恢复形成新版本并记录恢复人；恢复前仍检查当前版本和权限；账号停用、名称修改、执行人移除后历史仍可读；恢复不会恢复旧权限或绕过失效附件授权；管理员没有历史删除接口。

### T25 — 任务文档关联与基础搜索

- 依赖：T15、T21、T24。
- 目标位置：`apps/server/src/modules/search`、任务文档关联组件。
- 工作：同项目文档与任务链接、反向关联、项目任务搜索、当前文档正文搜索；中文子串语义、分页、长度限制及必要索引。
- 验收：链接无权限资源不泄露标题；搜索 SQL 先限制项目；中文、短关键词、代码文本有样例；历史版本不混入当前搜索；软删除/归档默认过滤正确；大数据量不依赖前端全量过滤。

### T26 — MCP 用户凭据管理

- 依赖：T09、T11、T06。
- 目标位置：`apps/server/src/modules/api-credentials`、个人凭据设置页。
- 工作：令牌生成与摘要、一次性展示、项目白名单、读写范围、到期、撤销和使用时间；凭据只能由所属用户管理。
- 验收：数据库和日志没有令牌明文；用户不能替别人创建凭据；范围不能超过当前项目角色；撤销/停用/移除成员后的新请求失败；长期连接不能绕过逐请求授权；展示掩码与复制流程可用。

### T27 — MCP 读取工具与协议适配

- 验收：两种实际客户端测试通过；项目白名单有效；历史与附件信息不越权；大结果有分页与上限；协议初始化、未知工具、无效参数和认证错误处理正确。

- 验收：读写凭据仍受角色限制；只读凭据全部写入失败；每次成功操作记录授权用户、凭据及来源；网页立即读到相同结果；无法无损转换的内容拒绝覆盖；没有删除、成员或角色管理工具；失败不留下半完成资源。

### T29 — 归档、软删除、恢复及成员移除联动

## 6. 范围变化时的调整原则

如果需要缩短首版周期，优先推迟暗色/多语言、额外视图、第三方集成、MCP 管理类能力和高级搜索。已确认的权限隔离、每次保存追溯、并发防覆盖及备份恢复不能作为省工期的删减项。

最终实现使用这些计划作为基线，但任务完成必须以实际代码和验证结果为证据，不能仅勾选文档。
