# 前端组件与样式方案

状态：用户已确认 Mantine 选型与统一样式方向。具体主题参数和样板页仍需在实施中验证，尚未进入实现。

## 目标

统一样式、复用可靠的成熟组件，参考 Kaneo 和 Plane 的简洁协作界面。采用自己的品牌、视觉细节和代码实现。

## 已确认的组件选型

采用 Mantine 作为唯一通用 UI 组件库，与 React、Vite、TypeScript 集成。优先复用 core、form、dates、notifications、modals、dropzone 中实际需要的能力；使用 Mantine 的 Tiptap 集成组织编辑器工具栏。开源许可及依赖兼容版本在实施前核对并锁定，不使用试验性版本作为首版基础。

Mantine 自身不替代 Wiki 版本、自动保存、权限、审计及业务状态实现，也不提供本产品完整看板；这些部分通过组合成熟组件与专用库实现。

## 样式与复用规则

- 全局主题集中定义字体、字号、间距、颜色、边框、圆角、阴影、组件尺寸和层级；页面使用统一主题变量。
- 使用 Mantine 主题及 Styles API；业务布局使用 CSS Modules，避免同时建立另一套 Tailwind 主题体系。
- 按钮、输入框、选择器、日期控件、菜单、弹窗、抽屉、消息提示优先使用 Mantine；不同时引入 Ant Design、MUI、shadcn/ui 等另一套通用组件系统。
- 任务卡片、状态标识、优先级标识、成员选择器、页面标题、筛选栏、空状态与错误状态建立项目级复用组件；只封装有稳定业务规则的组合，不为每个底层组件增加无意义包装。
- 全项目统一使用一套开源图标，具体图标库及许可在依赖选择时确定。
- 侧边导航、项目内任务与文档切换、任务列表和四列看板采用一致结构；表单、任务详情和文档页使用一致的保存反馈与错误提示。
- 保留组件库键盘操作与焦点管理，验证本项目组合后的可访问性；图标按钮须有可访问名称，状态不能仅依赖颜色表达。
- 以中性背景、清晰边界、适度紧凑的密度及少量强调色为视觉方向；首版主题、语言和响应式范围待细化。
- 看板拖拽使用成熟专用库，仍需提供无需拖拽的状态修改入口；编辑器和其他较重页面能力按需加载。

## 首轮 UI 验证

在铺开业务页面前建立可运行的样式样板页，包含按钮、输入、选择器、日期、菜单、弹窗、抽屉、通知、任务卡片、状态和优先级标识，以及加载、空白、错误、只读与保存反馈状态。

验证键盘使用、焦点、文字对比度、长标题、窄屏和表单错误，确保复用规则一致；样板页是内部开发验收工具，不作为新增产品功能。

## 选择依据

- Mantine 提供 React 常用组件、表单、日期、通知及 Tiptap 集成和 Vite 接入文档，适合减少基础控件的自行维护。
- shadcn/ui 的源码分发方式提供较强定制能力，但需要项目维护引入的组件源码；本项目优先采用统一依赖式组件库。
- Ant Design 是可选成熟方案；当前更偏好 Mantine 作为本项目协作型界面的统一基础。该选择不是对可靠性、性能或资源占用的未经测试保证。
