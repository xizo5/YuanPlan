# 首轮性能基线与优化

日期：2026-09-18。测试环境为本机 Windows、Node.js 22.22.1、PostgreSQL 17.9。既有授权范围：先补权限/故障回归，再推进主体功能性能；本轮不涉及生产部署。

## 首屏下载

采用构建 manifest 遍历入口和递归静态依赖，逐文件统计原始和 Node gzip 默认压缩字节数。动态入口不计入首屏，所有静态共享块计入，避免只看入口文件造成误判。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 首屏 JavaScript 原始字节 | 978636 | 709408 | -27.5% |
| 首屏 JavaScript gzip 字节 | 285872 | 214211 | -25.1% |
| CSS 构建体积（十进制 KB） | 279.01 | 251.85 | -9.7% |

项目页、设置/团队页使用 React.lazy 和 Suspense；编辑器继续保持按需加载。未使用的全局 Notifications 和日期/通知样式移除。`npm run bundle:report` 可复查当前结果。Vite 展示的 gzip 数字可能因压缩参数与此脚本不同而略有差异。

650KB 告警阈值保持原值；所有单包低于阈值不代表首屏总量低于阈值。拆包会使首次进入对应页面增加按需请求，需结合真实网络验证。

## 子任务统计查询

任务列表对每行分别计算子任务数量和已完成数量。原谓词只有 `parent_id`；已有索引为 `(project_id,parent_id)`。增加同项目条件，使查询可使用复合索引前缀，不改变归档/删除计数语义，无需迁移。

`npm run benchmark:tasks` 使用独立 `_test` 数据库，事务内生成 4000 父任务及 16000 子任务，查询看板待办首批 31 行；对比优化前后结果完全一致。两种 SQL 交替运行，各预热 3 次、采样 30 次，以减少固定运行顺序偏差。结束时回滚生成的数据，不删除已有记录或历史。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| SQL 往返 P50 | 9.249ms | 5.214ms |
| SQL 往返 P95 | 10.291ms | 6.190ms |
| 单次 EXPLAIN ANALYZE 执行 | 8.301ms | 4.835ms |
| 单次计划 shared hit blocks | 24217 | 20497 |

这是一次本机暖缓存查询对比，未包含 HTTP、权限事务、连接池争用、冷缓存、真实长正文、并发写入或历史增长。基准脚本复现固定看板查询形状；若 `listTasks` 查询改动，应同步校验脚本。不得将上述数字描述为整站 P95 或生产承载能力。
