# 项目概览跳转与范围筛选修复

## 问题与原因

- 从任务切换到概览后再次点击“查看全部”，地址更新但仍停留在概览。
- 标签页、搜索和筛选用 replaceState 更新地址，路由 hook 仍保留旧地址。显式导航的目标恰好等于旧地址时，React 跳过相同值更新，项目页不重新初始化。
- “需要关注”是复合范围：未完成，且逾期、截止日期在统计日期到 7 天后、高/紧急优先级满足任意一项。asOfDate 是判断范围的基准，不能直接当成独立截止日期条件。

## 修改

- 路由 hook 为每次显式导航和浏览器前进/后退增加 revision，保证目的地址与上次记录相同也能切换页面。普通标签切换、筛选输入及详情编辑继续在本页面维护状态。
- 范围筛选开启时，筛选面板增加只读“概览范围”“统计日期”及规则说明。普通截止日期控件用于用户额外指定的日期筛选。
- 保留取消范围、清空和隐藏子任务功能；全部完成时“需要关注”仍返回空列表。

## 验证

- 修改前浏览器回归准确复现：从带 attention URL 的任务页切到概览，再查看全部，任务标签仍是未选中。
- 修改后概览浏览器回归通过，覆盖相同地址跳转、前进/后退、范围/日期展示和取消、没有截止日期的高优先级任务、全部完成情况下的空范围、清空后恢复全部，以及手机宽度。
- 日历/时间线浏览器回归通过，覆盖视图切换、URL 刷新、详情修改日期和手动保存；没有影响编辑状态。
- 类型检查与构建通过。完整测试：11 个文件、97 项通过，新增全部完成的 attention 统计和查询一致性检查。
- 桌面筛选面板截图已检查（模拟任务数据）：`project-overview-focus-filters.png`，保存在本会话可视化目录。
- 本次未改动服务端筛选规则，也未改动真实项目数据；尚未部署生产环境。
