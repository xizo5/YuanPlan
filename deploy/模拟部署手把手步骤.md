# 模拟部署 · 手把手步骤卡

> 照着从上往下敲，每步都有 **命令 → 预期输出 → ✅ 验证点**。
> 出问题先看最后的【出错速查表】，再回来找我。
>
> 配套阅读：`模拟服务器部署实录.md`（讲原理、讲模拟与真机的差异）

---

## 开跑前：三个数、一个目录

| 变量 | 本文用的值 | 含义 |
|---|---|---|
| 宿主机 IP | `10.0.0.37` | 你电脑的局域网 IP（`ipconfig` 查） |
| 对外端口 | `18430` | 别人访问用的端口（映射出来） |
| 内层端口 | `18420` | 应用在容器里监听的端口 |
| 项目目录 | `/opt/yuanplan` | "服务器"上放项目的位置 |

**你要改参数，就改这几处**（后面命令里出现的地方我会标 `←改这里`）：

```
-p 18430:18420            ← docker run 的端口映射
APP_URL=http://10.0.0.37:18430   ← 必须是"你浏览器里输的地址"
HTTP_PORT=18420           ← 容器内监听端口，一般不用改
```

> **端口别撞车。** 跑之前确认 18430 没被占用：
> ```powershell
> netstat -ano | findstr ":18430"
> ```
> 没有任何输出 = 空闲，可以用。

**准备两个终端窗口：**
- 窗口 ①「宿主机」—— 敲 Windows 命令（下面的 **阶段 A、B、F 及以后**）
- 窗口 ②「服务器」—— 进容器后敲 Linux 命令（**阶段 C、D、E**）

> 命令我用 **PowerShell** 写（Windows 默认就有）。
> 如果你用 **Git Bash**，唯一区别见[A 节末尾的说明](#如果你用-git-bash)。

# 阶段 A · 宿主机：造一台"服务器"

## A1. 清理旧环境（第一次跑可跳过）

```powershell
docker rm -f yp-server
docker volume rm yp-server-docker
```

预期输出：`yp-server` 和一卷 ID，或者 `No such container` / `No such volume`（那就是本来就没有，正常）。

> ⚠️ `docker volume rm` 会**删掉"服务器"上所有数据**（镜像、数据库、上传文件）。
> 这正是"推倒重来"的意思，随时可以重跑。

## A2. 启动"服务器"

```powershell
docker volume create yp-server-docker
docker run -d --name yp-server --privileged -p 18430:18420 -v yp-server-docker:/var/lib/docker -e DOCKER_TLS_CERTDIR= docker:dind
```

**为什么是 `dind`**：这个容器内部会跑一个**自己的 dockerd**，有独立的镜像库、容器和数据卷 —— 等效于一台装了 Docker 的 Linux 机器。
（挂 `-v /var/run/docker.sock` 的普通容器不算，那用的是宿主机的 Docker。）

首次运行会先下载 `docker:dind`（约 17 秒）。

预期输出：一串 64 位容器 ID。

## A3. 等它就绪

容器起来了，但里面的 dockerd 还要几秒才能收命令。

```powershell
docker exec yp-server docker info --format "内层 dockerd 就绪：{{.ServerVersion}}"
```

如果报 `Cannot connect to the Docker daemon`，说明还在启动，**等 5 秒再敲一次**。

**✅ 验证点 A**：输出类似 `内层 dockerd 就绪：29.9.0`

# 阶段 B · 宿主机：把项目"上传"到服务器

真机上是 scp / U 盘 / rsync，这里用 `docker cp` 等价替代。

## B1. 在"服务器"上建目录

```powershell
docker exec yp-server mkdir -p /opt/yuanplan/deploy /opt/yuanplan/images
```

## B2. 传三个文件

```powershell
cd C:\Users\AI\Developer\YuanPlan-handoff

docker cp .\compose.yaml                  yp-server:/opt/yuanplan/compose.yaml
docker cp .\deploy\init-db.sh             yp-server:/opt/yuanplan/deploy/init-db.sh
docker cp .\images\yuanplan-images.tar.gz yp-server:/opt/yuanplan/images/yuanplan-images.tar.gz
```

**为什么只传三个**：

| 文件 | 作用 | 少了会怎样 |
|---|---|---|
| `compose.yaml` | 服务编排定义 | 没法 compose up |
| `deploy/init-db.sh` | 建 `yuanplan_migrator` / `yuanplan_app` 两个数据库角色 | 数据库起不来 |
| `images/*.tar.gz` | 两个镜像的离线包（213 MB） | 没有镜像可用 |

第三个大约 **9 秒**（Git Bash 下可能显示得慢，别急）。

**✅ 验证点 B**：检查文件到位、大小对得上

```powershell
docker exec yp-server ls -l /opt/yuanplan /opt/yuanplan/deploy /opt/yuanplan/images
```

期望看到：

```
/opt/yuanplan:            compose.yaml
/opt/yuanplan/deploy:     init-db.sh          (655 字节)
/opt/yuanplan/images:     yuanplan-images.tar.gz   (224330354 字节)
```

### 如果你用 Git Bash

在 A2、B1、B2 之前先加一行，否则容器内的**绝对路径会被 Git Bash 改写**（`/opt/...` 被替换成 `C:\Program Files...`）：

```bash
export MSYS_NO_PATHCONV=1
```

这是实测踩过的坑 —— 现象是报 `can't open 'C:/Program Files/.../opt/yuanplan'` 这种莫名其妙的错误。

# 阶段 C · 服务器：进容器、查环境

## C1. 进容器

```powershell
docker exec -it yp-server sh
```

> dind 是 Alpine 系统，只有 `sh`，**没有 `bash`**。

进去后提示符会变成 `/ #`。**从这里开始的命令都在这个窗口里敲。**

> Git Bash 下如果卡住没反应，改用 `winpty docker exec -it yp-server sh`，或者干脆换 PowerShell 窗口。

## C2. 环境自检（真机上第一件事永远是看环境）

```sh
docker --version
docker compose version
command -v openssl >/dev/null 2>&1 && openssl version || echo "openssl 缺失"
command -v ip >/dev/null 2>&1 && echo "ip 有" || echo "ip 缺失"
df -h /
```

**✅ 验证点 C**：对照表（这是本环境的实测值）

| 命令 | 期望 | 说明 |
|---|---|---|
| `docker --version` | `Docker version 29.9.0` | |
| `docker compose version` | `Docker Compose version v5.6.0` | 很多系统装了 docker 但**没有 compose 插件**，必须确认 |
| `openssl` | `OpenSSL 3.5.9` | 但最小化系统常缺，所以下一步的脚本要能降级 |
| `ip` | `ip 有` | 同上 |
| `df -h /` | 可用空间 **> 5 GB** | 要装下 1.5 GB 镜像 |

> 顺便可以试试 `hostname -I` —— 这个环境下会**直接报错**（BusyBox 版 hostname 没这个参数）。
> 记住这一点：**取 IP 不能只靠一条命令**。

# 阶段 D · 服务器：生成配置文件

## D1. 生成 `deploy/.env`

整段复制粘贴（含最后的 `EOF` 那一行）：

```sh
cd /opt/yuanplan

# 生成随机密钥：有 openssl 就用它，没有就退回 /dev/urandom（两者产出等长十六进制串）
gen() {
  if command -v openssl >/dev/null 2>&1; then
    openssl rand -hex "$1"
  else
    head -c "$1" /dev/urandom | od -An -tx1 | tr -d ' \n'
  fi
}

cat > deploy/.env <<EOF
APP_URL=http://10.0.0.37:18430
HTTP_PORT=18420
BIND_ADDR=0.0.0.0
INSECURE_HTTP=true
AUTH_SECRET=$(gen 32)
SETUP_TOKEN=$(gen 18)
POSTGRES_PASSWORD=$(gen 24)
MIGRATION_DB_PASSWORD=$(gen 24)
APP_DB_PASSWORD=$(gen 24)
EOF
```

没有报错就是成功了（heredoc 天生安静）。

## D2. 核对配置

```sh
cat deploy/.env
grep -c '^[A-Z_]*=' deploy/.env
```

**✅ 验证点 D**：9 行配置，`AUTH_SECRET` 是 64 位十六进制，且**每行末尾没有奇怪的 `^M`**

九个变量各自管什么（**输错后果最严重的三个我标了 🔴**）：

| 变量 | 值 | 作用 / 设错的后果 |
|---|---|---|
| `APP_URL` 🔴 | `http://10.0.0.37:18430` | **必须是别人浏览器里输的地址**。后端做精确 Origin 校验，不一致 → 所有写操作 403 `INVALID_ORIGIN` |
| `HTTP_PORT` | `18420` | 容器内监听端口 |
| `BIND_ADDR` 🔴 | `0.0.0.0` | 上游默认只绑 `127.0.0.1`，不改成 `0.0.0.0` → **局域网连不上** |
| `INSECURE_HTTP` 🔴 | `true` | 明文 HTTP 下必须开，否则 Secure Cookie 发不出去 → **能登录，一刷新就掉线** |
| `AUTH_SECRET` | 随机 64 位 | 换掉会让所有人掉线 |
| `SETUP_TOKEN` | 随机 36 位 | 等下初始化管理员要用，**记下来** |
| `POSTGRES_PASSWORD` | 随机 | postgres 超级用户 |
| `MIGRATION_DB_PASSWORD` | 随机 | 迁移角色（建表用） |
| `APP_DB_PASSWORD` | 随机 | 应用角色（日常读写，最小权限） |

> 想改地址/端口，现在改还来得及：
> ```sh
> sed -i 's|^APP_URL=.*|APP_URL=http://你的IP:你的端口|' deploy/.env
> ```

# 阶段 E · 服务器：导入镜像并启动

## E1. 导入镜像

```sh
docker load -i images/yuanplan-images.tar.gz
```

预期输出（约 17 秒）：

```
Loaded image: yuanplan:local
Loaded image: yuanplan-db:local
```

**✅ 验证点 E1**：

```sh
docker images
```

应看到 `yuanplan:local`（1.07 GB）和 `yuanplan-db:local`（434 MB）两条。

## E2. 启动

```sh
docker compose --env-file deploy/.env -f compose.yaml up -d --no-build
```

`--no-build` 很关键：镜像已经从 tar 导入，**不要现场构建**。

预期输出（顺序很关键，compose 会自动串起来）：

```
Container yuanplan-db-1 Created
Container yuanplan-migrate-1 Created
Container yuanplan-app-1 Created
Container yuanplan-db-1 Started
Container yuanplan-db-1 Healthy
Container yuanplan-migrate-1 Started
Container yuanplan-migrate-1 Exited          ← 正常！
Container yuanplan-app-1 Started
```

## E3. 看状态

```sh
docker compose --env-file deploy/.env -f compose.yaml ps -a
```

**✅ 验证点 E**：期望长这样

```
NAME                 STATUS                      PORTS
yuanplan-app-1       Up (healthy)                0.0.0.0:18420->18420/tcp
yuanplan-db-1        Up (healthy)                5432/tcp
yuanplan-migrate-1   Exited (0)                   ← 必须是 (0)
```

**三个必读点**：

1. **`migrate` 显示 `Exited (0)` 是正常的** —— 它是一次性容器，跑完迁移就退出。`(0)` 表示成功，非 0 才是失败。
2. `app` 的 `(healthy)` 可能要等 20~30 秒才出现，中间显示 `health: starting` 属正常。
3. 如果 `app` 一直不 healthy：
   ```sh
   docker logs yuanplan-app-1
   ```

**✅ 验证点 E-附加**：确认迁移真的跑完了（含本次新增的 0010）

```sh
docker exec yuanplan-db-1 psql -U postgres -d yuanplan -t -A -c "SELECT name FROM schema_migrations ORDER BY name;"
```

应列出 `0001` → `0010_credential_all_projects.sql`。

## E4. 退出容器

```sh
exit
```

回到 Windows 提示符。**下面的命令都在宿主机窗口敲。**

# 阶段 H · 熟悉一下运维命令（可选但建议做）

重新进容器（`docker exec -it yp-server sh`），然后：

```sh
cd /opt/yuanplan
C="docker compose --env-file deploy/.env -f compose.yaml"

$C ps -a                 # 看全部服务状态
$C logs --tail=30 app    # 看应用日志
$C restart app           # 重启应用（数据不丢）
$C down                  # 停掉全部容器（数据卷保留）
$C up -d --no-build      # 再起来
$C down -v               # ⚠️ 连数据卷一起删 —— 数据库和上传文件全没
```

**建议动手试一次 `down` → `up -d --no-build`** —— 亲眼确认数据还在。
（`down` 只删容器，卷保留；`AUTH_SECRET` 没变，所以登录状态也会保留。）

# 出错速查表

| 症状 | 原因 | 处理 |
|---|---|---|
| `docker: Error response from daemon: port is already allocated` | 18430 被别的程序占了 | 换端口：`docker run` 的 `-p` 和 `APP_URL` 一起改 |
| 容器里报 `Cannot connect to the Docker daemon` | dind 里的 dockerd 还没起来 | 等 5~10 秒重试 |
| `docker cp` 报 `can't open 'C:/Program Files/...opt/...'` | Git Bash 改写了容器内路径 | `export MSYS_NO_PATHCONV=1` |
| `docker exec -it` 卡住不动 | Git Bash 的 tty 问题 | 换 PowerShell，或前面加 `winpty` |
| compose 报 `Set APP_URL` / `Set AUTH_SECRET` | `.env` 没生成，或 `--env-file` 路径不对 | 确认在 `/opt/yuanplan` 下执行，且 `deploy/.env` 存在 |
| `migrate` Exited(**1**) | 迁移报错 | `docker logs yuanplan-migrate-1` |
| `app` 一直 unhealthy | 应用启动失败 | `docker logs yuanplan-app-1`（多半是数据库连接或密钥问题） |
| 浏览器打开报 **403 INVALID_ORIGIN** | `APP_URL` 和你浏览器地址不一致 | 用 `APP_URL` 里那个地址访问，或改 `.env` 后 `restart app` |
| **能登录，一刷新就掉线** | `INSECURE_HTTP` 不是 `true` | 改 `.env` 后重启 app |
| 局域网/手机打不开，本机能开 | Windows 防火墙拦了 18430 | 管理员 PowerShell 执行下方命令 |
| 网页白屏/404 | `app` 容器没起来 | 回去看 `docker compose ps -a` |
| 硬盘吃紧 | 内层镜像占了 ~2 GB | `docker rm -f yp-server && docker volume rm yp-server-docker` |

**放行防火墙（要用手机/别的电脑访问时才需要）** —— 管理员身份运行 PowerShell：

```powershell
New-NetFirewallRule -DisplayName "YuanPlan-Sim" -Direction Inbound -Protocol TCP -LocalPort 18430 -Action Allow -Profile Any
```

# 从"模拟"搬到"真机"，只改三处

| 项 | 本模拟 | 真服务器 |
|---|---|---|
| `APP_URL` | `http://10.0.0.37:18430` | `http://<服务器IP>:18420` |
| `HTTP_PORT` | `18420` | `18420`（不变） |
| 执行方式 | 要先 `docker exec -it yp-server sh` 进去 | **直接在服务器上敲**，没有这层包裹 |

其余命令（`docker load` / `docker compose up -d --no-build` / `ps -a` / `logs`）**一模一样**。
真机上还有两点不同：系统通常是 Ubuntu/Debian（有 `bash`，那段 heredoc 更好粘），
防火墙要用 `ufw allow 18420/tcp` 而不是 Windows 的 `New-NetFirewallRule`。
