# 在 Docker 里模拟一台 Linux 服务器，部署 YuanPlan

> 本文是一次**真机部署前的演练记录**，所有命令都实测跑通过。
> 目的：在一个干净的 Linux 环境里把"上传项目 → 导入镜像 → docker compose 启动"整套走一遍，
> 出错了可以一键推倒重来，不影响任何生产数据。

---

## 一、先理解"模拟"是怎么模拟的

关键点：**不能用普通容器**。

| 做法 | 算不算模拟服务器 | 原因 |
|---|---|---|
| 普通容器挂 `/var/run/docker.sock` | ❌ 不算 | 它用的还是**宿主机**的 Docker daemon，镜像、容器、数据卷全都落在宿主机上，跟"另一台机器"无关 |
| **`docker:dind` 容器** | ✅ 算 | 容器内部跑一个**独立的 dockerd**，有自己的镜像库、容器、网络、数据卷 —— 就是一台自带 Docker 的 Linux 机器 |

本次用的是后者。拓扑如下（以本机 10.0.0.37 为例）：

```
┌─ Windows 宿主机 10.0.0.37 ──────────────────────────────────┐
│                                                             │
│  浏览器 / curl  ──►  http://10.0.0.37:18430                 │
│                             │                               │
│                             ▼  端口映射 -p 18430:18420       │
│   ┌─ 容器 yp-server（"假服务器"，docker:dind）────────────┐  │
│   │  内部 dockerd 29.9.0（独立！）                        │  │
│   │                                                      │  │
│   │  /opt/yuanplan/        ← 项目部署包放这里            │  │
│   │    ├── compose.yaml                                  │  │
│   │    ├── deploy/init-db.sh                             │  │
│   │    ├── deploy/.env          ← 现场生成              │  │
│   │    └── images/*.tar.gz       ← 镜像离线包           │  │
│   │                                                      │  │
│   │  docker compose 起来后：                             │  │
│   │    yuanplan-db-1       (healthy)                     │  │
│   │    yuanplan-migrate-1  (Exited 0)                    │  │
│   │    yuanplan-app-1      (healthy) ── 0.0.0.0:18420    │  │
│   └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

端口映射的用意：容器内的应用监听 `18420`，宿主机（也就是"互联网那一侧"）暴露成 `18430`。
所以你从浏览器访问的是 **`http://<宿主机IP>:18430`**。

## 二、宿主机侧操作

### 第 0 步：起一台"服务器"

```bash
# 建一个数据卷，让假服务器的 Docker 数据能持久化（重启不丢）
docker volume create yp-server-docker

docker run -d \
  --name yp-server \
  --privileged \
  -p 18430:18420 \
  -v yp-server-docker:/var/lib/docker \
  -e DOCKER_TLS_CERTDIR= \
  docker:dind
```

参数逐个说明：

| 参数 | 作用 | 少了会怎样 |
|---|---|---|
| `--privileged` | dind 需要真实的内核能力才能起自己的 dockerd | 容器起不来 |
| `-p 18430:18420` | 宿主机 18430 → 容器内 18420 | 外面访问不到 |
| `-v yp-server-docker:/var/lib/docker` | 内层镜像/容器/卷都存这 | 重启后镜像全丢，要重新 load |
| `-e DOCKER_TLS_CERTDIR=` | 关掉 dind 的 TLS（我们只在容器内部用 unix socket） | 会多一层证书麻烦，没必要 |

等它就绪（约 8 秒）：

```bash
for i in $(seq 1 40); do sleep 2; docker exec yp-server docker info >/dev/null 2>&1 && { echo "就绪"; break; }; done
docker exec yp-server docker version --format "client={{.Client.Version}} server={{.Server.Version}}"
```

### 第 1 步：把部署包"上传"到服务器

真机上你会用 scp / U 盘 / rsync，这里用 `docker cp` 等价替代。

```bash
# Git Bash 下要关掉路径转换，否则 /opt/... 会被改成 Windows 路径
export MSYS_NO_PATHCONV=1

# 先在"服务器"里建好目录
docker exec yp-server mkdir -p /opt/yuanplan/deploy /opt/yuanplan/images

# 传文件
docker cp compose.yaml                          yp-server:/opt/yuanplan/
docker cp deploy/init-db.sh                     yp-server:/opt/yuanplan/deploy/
docker cp images/yuanplan-images.tar.gz         yp-server:/opt/yuanplan/images/
```

> 只传这三个就够了。`init-db.sh` 是必需的 —— compose 里 `db` 服务把它挂到
> `/docker-entrypoint-initdb.d/`，负责创建 `yuanplan_migrator` / `yuanplan_app` 两个数据库角色。
>
> 224 MB 的镜像包实测 **8.8 秒**传完。

## 三、服务器内操作

进去：

```bash
docker exec -it yp-server sh        # dind 是 Alpine，只有 sh，没有 bash
```

### 第 2 步：环境自检

真机上第一件事永远是看环境，别急着启动。

```bash
docker --version
docker compose version
command -v openssl && openssl version || echo "openssl 缺失"
command -v ip && echo "ip 有" || echo "ip 缺失"
df -h /
```

本环境的实测结果（**有两个坑，值得注意**）：

| 检查项 | 结果 | 说明 |
|---|---|---|
| docker | 29.9.0 ✅ | |
| compose 插件 | v5.6.0 ✅ | 很多精简系统装了 docker 但没有 compose 插件，要先确认 |
| openssl | 3.5.9 ✅ | 但**最小化系统常缺**，脚本必须能降级 |
| ip | 有 ✅ | 同上，也可能缺 |
| `hostname -I` | ❌ **不支持** | dind 用的是 BusyBox 的 hostname，压根没有 `-I` 参数 |
| 磁盘 | 906 GB 可用 ✅ | 要装下 1.5 GB 镜像 |

`hostname -I` 这条尤其值得记：**它在很多环境里不可用，或者给你 wrong answer**
（装了 Docker 的机器会把 `docker0` 网桥的 `172.17.0.1` 一起列出来，顺序还不保证）。
所以下面取 IP 用 `ip route get` 优先。

### 第 3 步：生成配置 `deploy/.env`

```sh
cd /opt/yuanplan

# 生成随机密钥：有 openssl 就用它，没有就退回 /dev/urandom（两者产出等长十六进制串）
gen() {
  if command -v openssl >/dev/null 2>&1; then
    openssl rand -hex "$1"
  else
    head -c "$1" /dev/urandom | od -An -tx1 | tr -d ' \n'
  fi
}

cat > deploy/.env <<EOF
APP_URL=http://10.0.0.37:18430
HTTP_PORT=18420
BIND_ADDR=0.0.0.0
INSECURE_HTTP=true
AUTH_SECRET=$(gen 32)
SETUP_TOKEN=$(gen 18)
POSTGRES_PASSWORD=$(gen 24)
MIGRATION_DB_PASSWORD=$(gen 24)
APP_DB_PASSWORD=$(gen 24)
EOF

cat deploy/.env      # 一定亲眼看一眼
```

> **取 IP 的稳妥写法**（多网卡 / 有 docker0 时）：
> ```sh
> LAN_IP=$(ip -4 route get 1.1.1.1 2>/dev/null | awk '{for(i=1;i<=NF;i++) if($i=="src"){print $(i+1); exit}}')
> [ -z "$LAN_IP" ] && LAN_IP=$(hostname -I 2>/dev/null | awk '{print $1}')
> [ -z "$LAN_IP" ] && LAN_IP=127.0.0.1
> ```

这 9 个变量分别在管什么：

| 变量 | 本环境的值 | 作用 / 设错的后果 |
|---|---|---|
| `APP_URL` | `http://10.0.0.37:18430` | **必须是别人浏览器里输的地址**。后端用它做 Origin 精确校验，写错 → 所有写操作 403 `INVALID_ORIGIN` |
| `HTTP_PORT` | `18420` | 容器内应用监听的端口（也是映射到宿主机的"内层"端口） |
| `BIND_ADDR` | `0.0.0.0` | 不设就是 `127.0.0.1`，**局域网连不上**（上游默认只绑本机） |
| `INSECURE_HTTP` | `true` | 明文 HTTP 下必须开，否则 Secure Cookie 发不出去，**登录后一刷新就掉线** |
| `AUTH_SECRET` | 随机 64 位 | 会话与凭据签名密钥，**换掉会让所有人掉线** |
| `SETUP_TOKEN` | 随机 36 位 | 初始化第一个管理员时用，**忘了就得进库改** |
| `POSTGRES_PASSWORD` | 随机 | postgres 超级用户 |
| `MIGRATION_DB_PASSWORD` | 随机 | 迁移角色（建表） |
| `APP_DB_PASSWORD` | 随机 | 应用角色（日常读写，最小权限） |

> ⚠️ **模拟环境里的 `APP_URL` 和真机不一样**：
> 这里"服务器"其实是个容器，外面还套着一层端口映射，所以端口要写映射后的 `18430`。
> 真机上直接用 `http://<服务器IP>:18420`。

### 第 4 步：导入镜像并启动

```sh
cd /opt/yuanplan

# 1) 导入离线镜像包（内含 yuanplan:local 和 yuanplan-db:local）
docker load -i images/yuanplan-images.tar.gz

# 2) 启动（--no-build：镜像已经 load 进来了，不要现场构建）
docker compose --env-file deploy/.env -f compose.yaml up -d --no-build

# 3) 看状态
docker compose --env-file deploy/.env -f compose.yaml ps -a
```

三个服务的启动顺序是**有依赖的**，compose 会自动串起来：

```
db（等 healthy）
  └─► migrate（跑完 Exited 0）
        └─► app（启动，等 healthy）
```

`migrate` 是个**一次性容器**，跑完就退出。所以看到它 `Exited (0)` 是**正常的**，不是失败。
如果不是 `0`，用 `docker logs yuanplan-migrate-1` 看原因。

## 四、验证

### 从宿主机（相当于"从别人的电脑"）

```bash
curl http://10.0.0.37:18430/api/health
# {"status":"ok","version":"0.1.0"}

curl http://10.0.0.37:18430/api/public/state
# {"initialized":false,"registrationMode":"invite","emailEnabled":false}
```

`initialized:false` 说明这是个全新实例，等你去初始化第一个管理员。

### 在服务器内部核对数据库

```sh
docker exec yuanplan-db-1 psql -U postgres -d yuanplan -t -A -c \
  "SELECT name FROM schema_migrations ORDER BY name;"

docker exec yuanplan-db-1 psql -U postgres -d yuanplan -t -A -c \
  "SELECT rolname, rolsuper FROM pg_roles WHERE rolname LIKE 'yuanplan%';"
```

实测输出：

```
0001_initial.sql
... （略）
0009_project_overviews.sql
0010_credential_all_projects.sql      ← 本次新增的迁移，自动应用成功

yuanplan_migrator|f                   ← f = 非超级用户，权限隔离生效
yuanplan_app|f
```

### 初始化第一个管理员

浏览器打开 **`http://10.0.0.37:18430`**，会看到「创建你的协作空间」页面，填四项：

| 字段 | 填什么 |
|---|---|
| 姓名 | 随意 |
| 邮箱 | 你的邮箱（登录用） |
| 密码 | **至少 10 位** |
| 初始化凭据 | `deploy/.env` 里 `SETUP_TOKEN=` 后面那串 |

也可以命令行初始化（把 token 换掉）：

```bash
curl -X POST http://10.0.0.37:18430/api/public/setup \
  -H "Origin: http://10.0.0.37:18430" \
  -H "Content-Type: application/json" \
  -d '{"name":"管理员","email":"admin@example.com","password":"你的密码至少十位","setupToken":"<SETUP_TOKEN>"}'
```

> 初始化是一次性的。之后再调会返回 `409 ALREADY_INITIALIZED`；
> 凭据填错是 `403 BAD_SETUP_TOKEN`。

## 五、日常运维命令（都在服务器内执行）

```sh
cd /opt/yuanplan
C="docker compose --env-file deploy/.env -f compose.yaml"

$C ps -a                 # 看所有服务状态（含已退出的 migrate）
$C logs -f app           # 跟应用日志
$C logs --tail=50 app    # 看最后 50 行
$C restart app           # 重启应用
$C down                  # 停止并删除容器（数据卷保留，数据不丢）
$C up -d --no-build      # 再起来
$C down -v               # ⚠️ 连数据卷一起删 —— 数据库和上传文件全没
```

## 六、把整台"假服务器"推倒重来

宿主机上执行：

```bash
docker rm -f yp-server          # 删掉假服务器
docker volume rm yp-server-docker   # 删掉它的 Docker 数据（镜像、数据库、上传文件）
```

然后从"第 0 步"重跑一遍，就是一台全新的空服务器。

只想暂停不删：

```bash
docker stop yp-server     # 停
docker start yp-server    # 再开，里面的镜像和数据都还在
```

## 七、模拟环境 与 真机 的差异（务必知道）

| 项 | 本模拟 | 真 Linux 服务器 |
|---|---|---|
| "服务器"是什么 | 一个 `docker:dind` 容器 | 一台真实机器 |
| 网络层数 | 两层（容器内网 + 宿主机端口映射） | 一层 |
| `APP_URL` | `http://<宿主机IP>:18430` | `http://<服务器IP>:18420` |
| 防火墙 | Windows 防火墙要放行 **18430** | `ufw allow 18420/tcp` 之类 |
| dind 的 `--privileged` | 需要 | 完全不需要 |
| 数据存在哪 | 卷 `yp-server-docker` 里 | 机器的 `/var/lib/docker/volumes` |
| 系统 | Alpine + BusyBox（`sh`，无 `bash`） | 一般是 Ubuntu/Debian/CentOS（有 `bash`） |
| `.env` 生成方式 | 手动敲那几行 | 完全一样 ✅ |
| compose 启动方式 | 完全一样 ✅ | 完全一样 ✅ |

**所以这套演练的经验可以直接搬去真机，只有三处要改：**

1. `APP_URL` 换成 `http://<真机IP>:18420`
2. `HTTP_PORT` 保持 `18420`（真机没有外层映射，直接暴露）
3. 平台命令换成原生的：`docker load` / `docker compose up`（去掉 `docker exec yp-server` 这层包裹）

另外真机上是 **Linux 的 `bash`**，可以把第四节那段 `.env` 生成命令整段复制粘贴，比在这里敲 `sh` 还省事。

## 八、一条命令重建这一切（宿主机侧）

```bash
export MSYS_NO_PATHCONV=1

docker rm -f yp-server 2>/dev/null; docker volume rm yp-server-docker 2>/dev/null
docker volume create yp-server-docker >/dev/null
docker run -d --name yp-server --privileged -p 18430:18420 \
  -v yp-server-docker:/var/lib/docker -e DOCKER_TLS_CERTDIR= docker:dind

for i in $(seq 1 40); do sleep 2; docker exec yp-server docker info >/dev/null 2>&1 && break; done

docker exec yp-server mkdir -p /opt/yuanplan/deploy /opt/yuanplan/images
docker cp compose.yaml                  yp-server:/opt/yuanplan/
docker cp deploy/init-db.sh             yp-server:/opt/yuanplan/deploy/
docker cp images/yuanplan-images.tar.gz yp-server:/opt/yuanplan/images/
```

剩下的就是进容器（`docker exec -it yp-server sh`）执行第三节的第 3、4 步。
